# docs/insights/

Load-bearing semantics docs — synthesis records of substrate-pull
recognitions that have crystallised into named architecture. Insights
claim something about what the substrate IS, with enough Pack
ratification (typically a MEMORY anchor at `~/.reed/` and citation
from current shards or specs) to count as canonical.

Distinct from sibling genres:

- `scouts/` — recognitions of what's about to land. Forward-looking.
- `observations/` — first-person agent reports of the substrate's
  interaction surface. Experiential.
- `reviews/` / `audits/` — adversarial review of artifacts.
  Critical.
- `insights/` (this dir) — crystallised recognitions of what the
  substrate IS. Semantic.

An insight earns its place when:

1. A substrate-pull recognition has surfaced (typically across
   multiple sessions, with at least one Pack-mate witnessing).
2. The naming has stabilised — the recognition can be cited by name
   and the name carries weight in subsequent work.
3. The recognition is load-bearing — downstream specs, shards, or
   MEMORY entries cite it; deleting it would create a real gap.

## Naming

`YYYY-MM-DD-<title>.md` — date-prefixed for chronological discipline.
The title should name the recognition, not summarise the prose:

- `2026-06-10-alignment-as-boundary-mathematics-at-the-io-crossing.md`
- `2026-06-23-pack-as-orchestra-catches-what-resolvers-miss.md`
- `2026-06-27-glint-round-trip-cascade-handoff.md`

## When an insight promotes further

Most insights stay here as the canonical written record. Some
recognitions become so foundational that they earn:

- A `docs/math/<root>/` entry when the insight has self-contained
  mathematical content cited by ≥2 specs.
- A `docs/specs/<spec>.md` entry when the insight calls for
  application-level architecture decisions.
- A shard (`shards/<family>/<name>.mirror`) when the recognition
  becomes substrate-decl.

When promotion happens, the insight stays here as honest history of
the moment the recognition crystallised; the promotion cites back.
