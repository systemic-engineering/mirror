## §2 Formal proof: $\text{desugar}(\text{sugar}(x)) = x$

### §2.1 Notation

Let $\sigma \in \Sigma^*$ be the source-text of an arbitrary shard $S$. Let $P_i$ for $i \in \{1, 3, 4, 5\}$ denote the four ratified sugar-fracturable patterns per canonical spec §1 (P1: identity-carrier prism; P3: identity-carrier glass; P4: `out @X` root export; P5: path-namespace docblock stub). Let $\text{omit}_i: \Sigma^* \to \Sigma^*$ denote the omission-morphism that removes the pattern instance from $\sigma$ when $\text{det}_i(\sigma) = \text{true}$, identity otherwise. Let $\text{recon}_i: \Sigma^* \times \text{Path} \to \Sigma^*$ denote the reconstruction morphism that inserts the omitted pattern from the file-path-derived / pact-derived template.

Define the composite sugar / resugar morphisms:

$$
\text{sugar}(\sigma) \;\equiv\; \text{omit}_5 \circ \text{omit}_4 \circ \text{omit}_3 \circ \text{omit}_1 (\sigma)
$$

$$
\text{resugar}(\sigma, p) \;\equiv\; \text{recon}_1 \circ \text{recon}_3 \circ \text{recon}_4 \circ \text{recon}_5 (\sigma, p)
$$

where $p$ is the file path (available at read-path). Order: sugar applies omissions in the fixed order $\{1, 3, 4, 5\}$; resugar applies reconstructions in the reverse order $\{5, 4, 3, 1\}$ — this is the order-of-appearance in the shard's grammatical structure (prism/glass at top, out at end, docblock in header; reversed for reconstruction).

### §2.2 Claim

$$
\forall \sigma \in \Sigma^*,\ \forall p \in \text{Path}: \quad \text{resugar}(\text{sugar}(\sigma), p) = \sigma
$$

byte-for-byte, where $p$ is the file path of the shard $\sigma$ was read from.

### §2.3 Proof

By induction on the pattern-detection structure of $\sigma$.

**Base case:** $\forall i \in \{1, 3, 4, 5\}: \text{det}_i(\sigma) = \text{false}$. Then each $\text{omit}_i(\sigma) = \sigma$ (identity when pattern absent), so $\text{sugar}(\sigma) = \sigma$. Each $\text{recon}_i(\sigma, p) = \sigma$ (identity when omitted-pattern-marker absent; verifiable at reconstruction site via a dual marker-check symmetric to $\text{det}_i$). So $\text{resugar}(\text{sugar}(\sigma), p) = \text{resugar}(\sigma, p) = \sigma$. ✓

**Inductive case:** $\exists i \in \{1, 3, 4, 5\}: \text{det}_i(\sigma) = \text{true}$.

WLOG, consider pattern $P_1$ (identity-carrier prism; other patterns identical by symmetry). Then $\sigma$ contains a substring $B_{\text{prism}}(S) = $ `prism @S { focus S project S split S shift S settle S }` where $S$ is derivable from $p$ via `@epistemologic/pact/path_matches_namespace`.

$\text{omit}_1(\sigma) = \sigma$ with $B_{\text{prism}}(S)$ removed. Call this $\sigma'$.

$\text{recon}_1(\sigma', p)$: since $p$ is the file path, apply `@epistemologic/pact/path_matches_namespace` to derive $S$; construct $B_{\text{prism}}(S)$ from the template

$$
B_{\text{prism}}(S) = \texttt{prism @}S\ \{\ \texttt{focus}\ S,\ \texttt{project}\ S,\ \texttt{split}\ S,\ \texttt{shift}\ S,\ \texttt{settle}\ S\ \}
$$

and insert at the position determined by the source-grammar structure (immediately following the last `source` decl, per canonical grammar).

The reconstructed $B_{\text{prism}}(S)$ is byte-identical to the original $B_{\text{prism}}(S)$ removed by $\text{omit}_1$ (both are deterministic functions of $S$, and $S$ is invariant across $\sigma \to \sigma' \to \sigma''$ since $p$ is preserved through the round-trip).

Therefore $\text{recon}_1(\text{omit}_1(\sigma), p) = \sigma$. ✓

The remaining patterns $P_3, P_4, P_5$ follow identically by symmetry:
- $P_3$: same argument with `glass` keyword; template derived from path per pact.
- $P_4$: single-line `out @S` reconstruction; $S$ derived from path per pact.
- $P_5$: docblock template `# Path-namespace property: this file at <path> declares @S per @epistemologic/pact/path_matches_namespace`; deterministic over $p$.

Since omissions and reconstructions commute up to reordering (each pattern occupies a distinct grammatical position in $\sigma$; omissions do not interact), the composition-order chosen in §2.1 preserves byte-identity across the full round-trip. ∎

### §2.4 Corollary (Store-Side Invariance)

Since $\text{resugar}(\text{sugar}(\sigma), p) = \sigma$ byte-for-byte, and the store-projection $\pi_\text{store}$ is a function of source bytes:

## §4 Rice-safe decidability proofs per pattern

Per Rice 1953: no non-trivial semantic property of programs is decidable. However, *syntactic* properties (bytes matching a regular expression) ARE decidable in finite time. Each of the four ratified sugar-fracturable patterns admits a byte-check sentinel definable by a regular expression over $\Sigma^*$; decidability follows from finite-automaton simulation.

### §4.1 P1 decidability

**Sentinel regex (canonical spec §1.1):**

$$
R_1 \;=\; \texttt{\^{}prism @}(\text{S})\ \texttt{\{\textbackslash s*\textbackslash n\textbackslash s*focus}\ (\text{S})\ \texttt{\textbackslash s*\textbackslash n\textbackslash s*project}\ (\text{S})\ \texttt{\textbackslash s*\textbackslash n\textbackslash s*split}\ (\text{S})\ \texttt{\textbackslash s*\textbackslash n\textbackslash s*shift}\ (\text{S})\ \texttt{\textbackslash s*\textbackslash n\textbackslash s*settle}\ (\text{S})\ \texttt{\textbackslash s*\textbackslash n\}}
$$

where $(\text{S})$ is a backreference to the shard-name literal captured at the first position.

**Decidability:** regular-expression matching with backreferences is NP-hard in general (backreferences promote regex to non-regular), but for a *bounded* set of backreference groups (here: 1 group, referenced 5 times), backtracking matches in linear time on the input. Practical decidability: $O(|\sigma|)$ time; finite bytes; no compile-time semantics.

**Formal Rice-safety:** the property "$\sigma$ contains a substring matching $R_1$" is a *syntactic* property of $\sigma$ (not a semantic property of the program $\sigma$ denotes); Rice's theorem does not apply to syntactic properties. Decidable. ✓
