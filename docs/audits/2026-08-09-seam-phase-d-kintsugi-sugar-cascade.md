## §2 Substrate-honesty adversarial checks

### §2.1 Round-trip fidelity audit (Mara §2, §3, math §2)

**Claim:** `desugar(sugar(x)) = x` byte-for-byte.

**Adversarial probe #1 — whitespace variation:** Mara's sentinel regex
uses `\s*\n\s*` between op lines. If a shard hand-authors the prism
block with `  focus X\n  project X` (two-space indent) vs `    focus X`
(four-space), the sentinel matches BOTH, but the omit-morphism removes
different byte-strings. The resugar-morphism produces the canonical
template with whatever indentation the compiler defaults to. If the
compiler's default indentation differs from the hand-authored file's
indentation, `oid_pre ≠ oid_post` — **round-trip fails byte-exactly**.

**SEAM-COUNTER-LEAN on §3.1 byte-exactness claim:** the current spec's
round-trip proof holds only under the assumption that the compiler's
canonical template indentation matches every shard's hand-authored
indentation. This is empirically-FALSE in the general case (Reed
recently committed shards with varying indentation per author-preference).
Two options for resolution:
- (a) **Normalize source at write-path** — before hashing at store,
  canonicalize whitespace within omit-eligible blocks. Store-OID becomes
  indentation-invariant. Requires §3.3 to hold at CANONICALIZED byte
  altitude, not raw source byte altitude.
- (b) **Preserve indentation in template** — extend the omit-morphism
  to CAPTURE original indentation as a byte-preserving parameter; the
  resugar-morphism uses the captured indentation. Sugar rule remembers
  the shape it omitted.

**Recommended: (b)** — preserves the byte-exactness claim as-stated;
adds a small parameter to the omit-morphism. Mara-lean (b) is
composition-honest.

**Adversarial probe #2 — comment interleaving:** if a shard has
`# comment\nprism @X { focus X ...`, the sentinel regex `^prism @<S>`
matches at line-start after comment. Omit-morphism removes the prism
block cleanly. Resugar-morphism re-inserts at "the position determined
by the source-grammar structure (immediately following the last `source`
decl)" per math §2.3. But if the original position was IMMEDIATELY
AFTER a comment, and the resugar rule inserts after last-source-decl,
positions may differ. **SEAM-QUESTION**: math §2.3's
"reconstruction position" heuristic needs strengthening for the general
case where shards have comments interleaved.

**Adversarial probe #3 — `prism @glass` identity in `glass.mirror`:**
`shards/glass.mirror` line ~89 declares `prism @glass { focus glass ...
settle glass }`. This IS a P1 identity-carrier pattern per Taut §1.1
regex. But `shards/glass.mirror` is exempt per Mara-Q3. The
`@kintsugi/fracture/prism_boilerplate.detect` must have hardcoded
fixed-point-exemption logic for BOTH `shards/prism.mirror` and
`shards/glass.mirror`. Mara §9 [ALEX-Q3] correctly identifies this;
Seam-verdict is **SEAM-RATIFY** on the exemption but the detector's
implementation must not accidentally sugar these two.
