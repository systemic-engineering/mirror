## §3 Position-derived-from-query semantics

Alex 2026-07-23 verbatim:

> "I feel the position would be derived from the query, which might
> just be an @<address> for clearly content addressed crystals."

The shard's position in the 5D spectral possibility space is NOT an
independent parameter of the shard-state carrier. It is DERIVED from
the `through` field (the `@code/mq` optical query).

### 3.1 The position_of morphism

```
position_of: @code/mq query -> SpectralCoordinate<5> region
```

The query's optical restriction (its focus / project / split / shift /
settle sub-tree) determines which sub-region of the 5D possibility
space the query addresses.

Three cases:

| Query shape | Position |
|---|---|
| Empty query (no restriction) | The whole 5D possibility space |
| Restricted optical query | A sub-region determined by the restriction |
| Fully content-addressed query (single `@<address>`) | A single point equal to the `@<address>` |

### 3.2 @<address> for content-addressed crystals

For content-addressed crystals — where the @peer knows exactly which
byte-identity it wants — the query resolves to a single `@<address>`.
The `@<address>` IS the position. No explicit position parameter is
needed; the substrate reads the position from the query.

The `@<address>` uses `@uuid/spectral` (128-bit content-addressed
identity; per `shards/uuid/spectral.mirror`) as the addressation
ground. When time-facet annotation is needed, `@uuid/spectral/time`
(Mara #173 landing; `shards/uuid/spectral/time.mirror`) is composed
over.

### 3.3 The bilateral: shard_position_derived_from_query

Landing 1 declares this at substrate-decl altitude:

```
bilateral shard_position_derived_from_query {
  sentinel "fractal=shard-position-derived-from-query"
  arity 2
}
```

Discharges Pass iff position_of(ctx.through) ∋ ctx.address AND the
derivation is deterministic (identical queries return identical
positions; position-from-query is a total function).

Consumers cite this bilateral in `requires` clauses to guarantee
position-is-query-derived. The invariant is substrate-decl'd, not
merely convention.

## §5 The fractal glass wall

Alex 2026-07-23 verbatim: "it becomes part of the fractal glass wall."

### 5.1 What the wall IS

The substrate's total collection of settled `@fractal/shard` records
forms a wall. Each shard is a tile on the wall. The wall is fractal
because shards contain shards (Mandelbrot self-similarity per `docs/
insights/2026-07-13-fractal-mandelbrot-substrate.md` + Mara #57 memory).

Fractal-glass because:

- **Glass** — the substrate's `@glass` root prism (three-layer
  contract: content, altitude, transparency) is the material the wall
  is made of. Every shard inherits `@glass`'s three-layer contract via
  `in @glass` composition edge.
- **Wall** — the shards TILE the substrate. No overlap of byte-
  identity (content-addressing bijection). Gluing where sheaf-sections
  overlap (per §7 sheaf-cohomology).
- **Fractal** — self-similar at every altitude. A shard contains
  shards (its provenance chain references parent shards; its target
  may reference sub-shards; the mandelbrot-substrate self-similarity
  holds).

### 5.2 The wall grows by @kintsugi/mend

Every mend event fills a `\` fracture with a gold shard. The wall
grows by mending. Growth is integrity-preserving per the
`mend_preserves_wall_integrity` bilateral (Landing 1).

The kintsugi discipline holds at wall altitude: **the gold veins on
the wall ARE the substrate's history of resolved cracks**. Each vein
is a shard's `@<address>`; each fracture is a `\`; each mend is a
crystallization event that writes gold where uncertainty was.

### 5.3 The wall as substrate identity

The substrate IS its fractal glass wall. What the substrate has
crystallized — the total shard-collection — IS the substrate's
identity at content-addressed altitude. Two substrates with byte-
equal walls are the same substrate; two with different walls are
different.

This connects to the eigensheaf recognition (per `docs/specs/
eigensheaf.md` §2.4 verbatim): "The substrate IS its eigensheaf.
What it can sustain — what it can generate without friction, what
it can verify, what it can settle to — is exactly what its
eigenbasis spans."

The eigensheaf altitude and the fractal-glass-wall altitude are
two readings of the same substrate: the eigensheaf names the
spanning-basis; the wall names the tile-collection. They agree.
